# Typography

Typography carries most of a product's personality. It is decided first and
held to a system. Type choice is the single strongest signal of whether a
product was designed or generated.

## The font blacklist (never use without explicit justification)

These fonts are the fingerprints of generic AI output. Using them without a
specific, defensible reason tied to the product is a blocking finding:

- **Inter** — the default "modern" sans. Using it signals "I didn't choose."
- **Roboto** — the Android/system default. No personality.
- **Arial** — the fallback of last resort. Never a design choice.
- **Space Grotesk** — the "I want to look techy" default. Overused.
- **System font stacks as a primary choice** — legitimate for utilities and
  dashboards where performance is the priority, but never as a shortcut to
  avoid choosing a typeface.

**Why:** These fonts appear in the vast majority of AI-generated products. A
designer seeing them immediately thinks "generic." The goal is a product that
looks deliberately chosen, not defaulted.

## Concrete Font Pairings (Google Fonts, License-Safe)

All pairings below use Google Fonts or Fontsource. Each is a deliberate choice
tied to a specific product personality. **Do not reach for Inter or Roboto —
pick from this list or choose with equal intentionality.**

### Pairing 1: Editorial Magazine
**Display:** Playfair Display (serif, high contrast)
**Body:** Source Sans 3 (clean humanist sans)
**Personality:** confident, structured, story-led
**Best for:** magazines, publishing, essays, media brands
**Rationale:** The high-contrast serif creates editorial authority. Source Sans
provides clean readability at body sizes without competing.

### Pairing 2: Developer Tool
**Display:** IBM Plex Sans (neutral, engineered)
**Body:** IBM Plex Mono (monospace for code/data)
**Personality:** technical, legible, dense
**Best for:** dev tools, APIs, documentation, code editors
**Rationale:** IBM Plex was designed for technical contexts. The mono variant
handles code naturally; the sans provides hierarchy.

### Pairing 3: Brutalist Studio

**Body:** Work Sans (neutral grotesque, good at small sizes)
**Personality:** raw, honest, structural
**Best for:** developer tools, studios, counter-culture brands
**Rationale:** Archivo Black has weight and presence. Work Sans provides
readability without softening the brutalist edge.

## Strategy rules

- **One or two families max.** A single family with a clear scale is often
  strongest. Two families only when they do genuinely different work (e.g.,
  display serif for headings + humanist sans for body). Three families without
  a strong reason is a smell.
- **Pair by contrast in structure, not by accident.** Pair a serif display with
  a neutral sans, or a grotesque with a humanist — the pairing should be
  *planned*, not two fonts that both look nice.
- **Choose typefaces with character.** The typeface should reinforce the
  product's personality (see `design/design-diversity.md`). A law firm's
  editorial serif and a dev tool's monospace say completely different things.
  Use that.
- **Licensing matters.** Only use fonts whose license permits the product's
  distribution (see `marketplace/compliance.md`). Self-hosting is safest.
  Google Fonts and Fontsource are good sources for license-safe web fonts.
- **Variable fonts are preferred** when loading web fonts — they give a full
  weight range from a single file.

## Choosing a typeface (the decision process)

1. Read the product's personality from `design/design-direction.md`.
2. Match it to a design language in `design/design-diversity.md`.
3. Pick a typeface from the pairings above (or one with equal intentionality)
   that embodies that language.
4. If pairing, choose two typefaces with genuine structural contrast.
5. Document the choice and its rationale in the design direction brief.

## The type scale

- Build a small, rational scale (typically 5–7 steps) and use it consistently.
  Define it in tokens.
- Headlines: size for the content, cap measure sensibly (aim for ~45–75
  characters per line on body text).
- Body text: limit paragraph width to 65–75 characters for optimal readability.
  Use `text-wrap: balance` on headings and `text-wrap: pretty` on paragraphs to
  avoid orphaned words.
- Body: 16px baseline minimum for primary reading; smaller is allowed for
  labels, metadata, and dense data contexts, but keep legibility.
- Line-height: ~1.5 for body text (comfortable reading), ~1.2 for headings
  (tight, confident).
- Data/numbers: use tabular figures (`font-variant-numeric: tabular-nums`) in
  tables, metrics, dashboards, prices, and dates so columns align vertically.
- Uppercase labels: increase letter-spacing slightly (e.g., 0.05em) for better
  readability and a more intentional look.

## Fluid Type Scale (CSS Implementation)

Use `clamp()` for responsive typography that scales smoothly between mobile
and desktop without breakpoints.

```css
:root {
  /* Fluid type scale — mobile to desktop */
  --text-xs: clamp(0.694rem, 0.66rem + 0.17vw, 0.8rem);
  --text-sm: clamp(0.833rem, 0.78rem + 0.27vw, 1rem);
  --text-base: clamp(1rem, 0.92rem + 0.4vw, 1.25rem);
  --text-lg: clamp(1.2rem, 1.07rem + 0.63vw, 1.563rem);
  --text-xl: clamp(1.44rem, 1.24rem + 1vw, 1.953rem);
  --text-2xl: clamp(1.728rem, 1.43rem + 1.49vw, 2.441rem);
  --text-3xl: clamp(2.074rem, 1.64rem + 2.17vw, 3.052rem);
  --text-4xl: clamp(2.488rem, 1.87rem + 3.09vw, 3.815rem);
  --text-5xl: clamp(2.986rem, 2.11rem + 4.38vw, 4.768rem);
  --text-hero: clamp(3.583rem, 2.36rem + 6.11vw, 5.96rem);
}
```

### Applying the scale

```css
body {
  font-size: var(--text-base);
  line-height: 1.6;
}

h1, .heading-1 { font-size: var(--text-5xl); line-height: 1.1; letter-spacing: -0.03em; }
h2, .heading-2 { font-size: var(--text-4xl); line-height: 1.15; letter-spacing: -0.025em; }
h3, .heading-3 { font-size: var(--text-3xl); line-height: 1.2; letter-spacing: -0.02em; }
h4, .heading-4 { font-size: var(--text-2xl); line-height: 1.25; letter-spacing: -0.015em; }
h5, .heading-5 { font-size: var(--text-xl); line-height: 1.3; letter-spacing: -0.01em; }
h6, .heading-6 { font-size: var(--text-lg); line-height: 1.4; letter-spacing: 0; }

p, .body { font-size: var(--text-base); line-height: 1.6; }
small, .caption { font-size: var(--text-sm); line-height: 1.5; }
.label {
  font-size: var(--text-xs);
  line-height: 1.4;
  letter-spacing: 0.05em;
  text-transform: uppercase;
}
```

## Typography Implementation Details

### Letter-spacing rules

```css
/* Display headlines: tight, confident */
.heading-hero {
  letter-spacing: -0.04em;
}

.heading-1 { letter-spacing: -0.03em; }
.heading-2 { letter-spacing: -0.025em; }
.heading-3 { letter-spacing: -0.02em; }

/* Body text: natural, no adjustment */
p { letter-spacing: 0; }

/* Uppercase labels: slightly open for readability */
.label-upper {
  letter-spacing: 0.05em;
  text-transform: uppercase;
}

/* Small caps / metadata: open */
.meta {
  letter-spacing: 0.02em;
}
```

### Line-height rules

```css
/* Display: tight, confident */
.hero-title { line-height: 1.0; }
h1 { line-height: 1.1; }
h2 { line-height: 1.15; }
h3 { line-height: 1.2; }

/* Body: comfortable reading */
p { line-height: 1.6; }
body { line-height: 1.6; }

/* Small text: slightly more open */
small { line-height: 1.5; }
.caption { line-height: 1.5; }

/* Labels: tight */
.label { line-height: 1.3; }
```

### Font feature settings

```css
/* Tabular numbers for data contexts */
.metric, .price, .date, .table-data, [data-tabular] {
  font-variant-numeric: tabular-nums;
}

/* Stylistic alternatives (when available) */
.fancy-heading {
  font-feature-settings: "liga" 1, "calt" 1, "kern" 1;
}

/* Oldstyle figures for editorial body text */
.editorial-body {
  font-feature-settings: "onum" 1;
}

/* Small caps for abbreviations */
abbr {
  font-variant-caps: all-small-caps;
  letter-spacing: 0.05em;
}
```

### Text wrapping

```css
/* Headlines: balance line lengths */
h1, h2, h3 {
  text-wrap: balance;
}

/* Body paragraphs: prevent orphaned words */
p {
  text-wrap: pretty;
}

/* Captions and metadata: allow natural wrapping */
.caption {
  text-wrap: auto;
}
```

### Display typography (large headlines)

```css
/* Hero: oversized, tight tracking, bold weight */
.hero-title {
  font-size: var(--text-hero);
  line-height: 1.0;
  letter-spacing: -0.04em;
  font-weight: 700;
  text-wrap: balance;
}

/* Section heading: strong presence */
.section-title {
  font-size: var(--text-5xl);
  line-height: 1.1;
  letter-spacing: -0.03em;
  font-weight: 700;
}

/* Sub-heading: clear hierarchy */
.section-subtitle {
  font-size: var(--text-xl);
  line-height: 1.4;
  letter-spacing: -0.01em;
  font-weight: 400;
  color: var(--color-text-muted);
}
```

## Hierarchy without decoration

- Hierarchy comes from size, weight, case, color contrast, and spacing — not
  from underlines, shadows, or gradient text.
- Reserve weight contrast for emphasis; don't set everything to the same weight.
- Keep letter-spacing deliberate: tight for large headings, slightly open for
  small caps/uppercase labels; never random.

## Accessibility

- Minimum 4.5:1 contrast for body text, 3:1 for large text (WCAG AA).
- Never convey meaning by typography alone (e.g., color-coded status).
- No text inside images for real content.
- Fluid type via `clamp()` for responsive scaling where it genuinely helps.
- Respect the user's font-size settings: don't lock tiny fixed sizes everywhere.
- Font sizes below 16px on mobile are a readability failure.
